# macos_update — the update half of the `up` command: system-wide package & tool updates

- `update_all.sh` is the update phase that `up` runs. `up` (alias in `zsh/aliases.sh`) sources `macos/update_all_and_cleanup_all.sh`, which runs this `update_all.sh` first, then `macos_cleanup/cleanup_all.sh` — both as **child zsh processes** (not sourced), then reloads the shell.
- It updates everything in one pass: Homebrew, Mac App Store (`mas`), VSCode extensions, Appium plugins, .NET tools, pre-commit hooks, Oh My Zsh, Powerlevel10k, TLDR/Bat caches, Atuin sync
- Runs `brew bundle dump --force --describe` to sync the live Homebrew state back into `homebrew/brewfile` — so the brewfile is regenerated from the machine, not hand-edited here.
- Refreshes the RAG index by sourcing `$DIR_RAG/rag.sh` (the `~/projects/rag` repository) and running `rag refresh` (best-effort; skipped when rag is not cloned, failures tolerated if litellm/qdrant are down).
- Also triggers other dotfiles subsystems: `docker/up.sh`, `$DIR_SERVICES/immich/sync.sh` (skipped where that project is absent), `$DIR_LITELLM/scripts/check-models.py`, `$DIR_SKILLS/shared/skills-repos/update.sh`, `docs/keyboard/generate.py`, and `rtk gain`.
- strips `com.apple.quarantine` xattrs from `/Applications/*.app` after upgrades); `update_all.sh` sources it and calls it.
- **Static Data Compression** runs `applesauce/compress.sh` last, after every step that could rewrite an SDK — decmpfs is dropped on write, so compressing earlier would just be undone. Everything about it (tool choice, thresholds, the `.dotnet/packs` trap, app-bundle permissions) lives in `applesauce/AGENTS.md`.
- **Security Guards** section catches silent drift on settings whose failure mode is invisible — the OS looks healthy either way, so only an explicit check surfaces them:
  - *Screen lock* must be `immediate`, else a closed lid leaves the Mac unlocked for that long. `sysadminctl -screenLock status` needs no auth, reports on **stderr** and always exits 0 — parse the string, never the exit code; and the healthy value is the word `immediate`, not `0 seconds`. The reset does need auth, so it runs `-password -` (interactive prompt), which only fires on drift.
  - *XProtect* signatures. Real incident: they sat two months stale because `ConfigDataInstall` was 0. On Tahoe the enforced copy lives in `/var/protected/xprotect` and is converted from what Software Update fetches, so that one key freezes both channels — and the legacy `XProtect.bundle` path reports a number that is not what the system enforces. Use `xprotect version`. A **missing** pref key is not proof of "off" (Apple omits it when the GUI writes it), so only an explicit `0` is flagged; `softwareupdate -l --include-config-data` (~7 s) is the ground truth. This guard warns and never fixes: `up` is deliberately sudo-free and both remedies need root.
- Invariant: per repo fail-fast policy, do not add existence/availability guards around tools — missing tools should fail loudly. Per-step `|| echo` fallbacks exist only for network-dependent services (rag, litellm, immich/i9) that are expected to be intermittently offline. `|| true` is used only where non-zero status is informational, not a failure (`brew doctor` warnings, locked in-use files).
- **`up` asks for the password once.** `macos/update_all_and_cleanup_all.sh` runs `sudo -v` first and keeps the timestamp alive in the background until the run ends; before that, casks in a long `brew upgrade` and then the cleanup each asked again.
- **«Требует внимания».** The same script exports `UP_ATTENTION` (a temp file) and prints it at the end. A step reports a problem with one line: `attention "…"` in these scripts (`functions.sh`, `macos_cleanup/helpers.sh`, where every `spinner_stop_error` also lands there), or `>> "${UP_ATTENTION:-/dev/null}"` from another repository (skills-repos, immich, LiteLLM model check). Only problems the owner should act on — not progress.
- **Static Data Compression prints only what it compressed**: nothing at all, heading included, when no file changed. On a terminal a live line names the app being compressed and is erased afterwards; run by hand, an unchanged run ends with «nothing new to compress».
