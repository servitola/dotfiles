# macos — one-shot macOS system configuration: `defaults` tweaks, per-extension default apps, Dock, hosts.

- `set_defaults.sh` is the main entry: idempotent `defaults write` / PlistBuddy tweaks across Finder, keyboard, Safari, Transmission, Dock, Software Update, dark mode, etc. Run from repo root (sources `zsh/functions.sh` and `helpers/` by relative path); needs `sudo`. Prints a changed/already-set summary. Shortcuts (symbolic hotkeys, app global hotkeys, menu shortcuts) are not written here: `install/17-shortcuts.sh` runs `docs/keyboard/tools/shortcuts.py apply` after Homebrew and the apps are installed.
- `shortcuts.toml` declares the shortcut state that lives in macOS preferences — every `com.apple.symbolichotkeys` id, app global hotkeys, `NSUserKeyEquivalents` menu shortcuts. Regenerate with `shortcuts.py capture --write`, diff with `shortcuts.py check`; the gotchas (sandboxed apps are unwritable, `killall cfprefsd` + relaunch) are in that script's docstring. See `docs/keyboard-setup.md` → *Machine shortcuts*. App hotkeys come in several storage formats (`keyboardshortcuts`, `masshortcut`, `carbon-dict`, `ice`, `services`), one `format` per `[[app]]` row; a format is only read where `REGISTRY` in `shortcuts.py` lists the app, because no OS API enumerates registered global hotkeys. Ice is read-only and Day One sits in a group container, so `apply` refuses or skips those with the Settings path to use instead. `shortcuts.py taps` lists who holds CoreGraphics event taps on the keyboard.
- `set_default_apps.sh` binds extensions and UTIs to apps from one `HANDLERS` dict. Add an app or an extension there, nothing else. Two rules it enforces: the write goes through `defaults import` (a raw `.plist` write is silently reverted by cfprefsd), and every bundle id must belong to an installed app (a dead id makes macOS ask which app to use). Full filenames (Brewfile/Makefile/…) have no mechanism and are absent. Check a binding by asking `NSWorkspace.urlForApplication(toOpen:)` about a real file — anything that resolves by UTI cannot see the extension bindings.
- Install step 10 (`install/10-dock.sh`) sets the Dock: on the right, only Apps in it. It writes only what differs and restarts the Dock only then.
- `helpers/` holds sourced functions: `set_macos_default_if_different.sh` and `set_plist_value_if_different.sh` (only write when current value differs, drive the summary counters), `colors.sh`, `spinner.sh`, and `try_to_clean_directory.sh` / `try_to_clean_by_pattern.sh` (the latter two are shared with `macos_cleanup/`).
- `hosts` is symlinked to `/etc/hosts` by install step 5; it null-routes telemetry domains (Anthropic, VS Code, Microsoft, analytics).
- Run by the installer: `set_defaults.sh` is step 1, `set_default_apps.sh` step 9. Not run automatically otherwise.
- Standalone utilities (not part of `make`): `git-repo-analyzer.sh` (find/prune git repos), `move-addictive-drums-to-external.sh` (migrate AD2 samples to external drive + symlink), `update_all_and_cleanup_all.sh` (convenience wrapper that sources `macos_update/update_all.sh` then `macos_cleanup/cleanup_all.sh`).
- Sibling dirs `macos_update/` (brew/npm/macOS updates) and `macos_cleanup/` (cache/log pruning) are separate; this dir is config/setup, they are maintenance. They meet only via `update_all_and_cleanup_all.sh` and the shared `helpers/try_to_clean_*` scripts.
